# distill 模式：凝练主文档

**有损压缩。** 输入是干净的终态上下文，输出是能约束其他对话的 `method-core.md`。

## 输入

- 一份 `./method/context-clean-*.md`（必填）
- 现有 `method-core.md`（若有，取其 `version` 作 `supersedes`）

不接受的输入：原始对话、修改会话的产出、未经清理的笔记。有损步骤只允许在干净源上做。

## 产物

| 文件 | 动作 |
|---|---|
| `./method/method-core.md` | 覆盖写（旧版先进 `_archive/`） |
| `./method/CHANGELOG.md` | 追加一条，**永不改写已有条目** |
| `./method/_archive/method-core-v<旧版本>.md` | 归档 |

模板与板块填写指引：`template-method-core.md`。

## 步骤

1. 读 `context-clean-*.md` 全量；读现有主文档取 `version`。
2. 按六板块组织。**§2 只写逻辑链与结构，细节留给 §1/§5**——细节写进内核是超预算的头号原因。
3. §3 必须含**禁替代表**：术语 → 禁止的变体写法。来源是清理产物的「术语沿革」表。
4. §4 拆两层：`4.1 事实红线`（陈述层，可逐字入稿）、`4.2 行为禁令`（指令层）。
5. 预算检查 → 生成**附录 A 舍弃清单**；拿不准归属的进**附录 B 存疑清单**。
6. 写主文档 → 归档旧版（首版跳过）→ 追加 CHANGELOG（首次运行创建文件并写 `v1.0.0` 条目）。
7. 停下等人工：**全读简化版**，见下方审查提示。

## 预算（关键）

### 计量口径

- 按字符数计（含标点），表格与代码块计入。
- **不计**：YAML frontmatter、附录 A、附录 B（审计元数据，不是约束内容）。
- **不计入预算**：§2、§3、§4（地板，全量）。
- **计入预算**：§1 + §5 + §6 + 任何写进正文的补充细节，合计 **≤ 8000 字**。

### 地板为什么是这三块

| 板块 | 为什么不可节略 |
|---|---|
| §2 内核逻辑链 | 整份文档存在的理由。删了，剩下的只是一堆条目 |
| §3 术语与禁替代表 | 术语漂移是头号污染路径；删掉术语表恰好是在制造漂移 |
| §4 论述红线 | 删红线不是「短一点」，是**反向授权**——下游会认为没写就是可以改 |

地板没有长度上限，但有隐性上限：**把细节写进内核，它就会以地板之名无限膨胀**。

### 8000 字分配建议

| 板块 | 建议上限 | 说明 |
|---|---|---|
| §1 主题与问题 | 1200 | 一段话够用，多出来的是背景铺陈 |
| §5 可调整项 | 2500 | 表格化，比散文省 |
| §6 任务聚焦 | 1000 | 每次替换，不需要长期细节 |
| 补充细节余量 | 3300 | 例证、边界情形、易错点 |

总额 ≤ 8000；单块超了在块内先砍，不跨块挪用余量。

### 取舍顺序

1. **先砍具体细节**：例证、背景铺陈、实现步骤、文献性说明、比喻。
2. **再砍论证结构的展开**：只留环与环的连接，删掉每环内部的层层解释。
3. **还不够 → 升级，不动地板。**

「论证结构」指内核的**展开方式**，不是 §2 本身。§2 的五个环一个都不能少，能删的只有环内部的注解。

### 超预算的升级方案

不许砍红线。给人工三个方案：

| 方案 | 做法 | 适用 |
|---|---|---|
| A 拆分 | §5、§6 独立成文件，主文档只留 §1–§4 | 可调整项太多 |
| B 分章节 | `method-core.md` 放全局；章节级约束放 `method-<章节>.md` | 论文有多个方法分支 |
| C 降级 | 把某条红线明确降为「可调整项」，需人签字 | 极少；唯一允许动地板的情形 |

方案 C 必须：人签字 → CHANGELOG 记 `floor-change` → 受影响章节列入兼容性检查。**本模式不得自行选择 C。**

## 附录 A 舍弃清单

```markdown
| 编号 | 被舍弃内容 | 出处 | 舍弃理由 | 可恢复性 |
|---|---|---|---|---|
| D1 | <…> | C12 | 超出预算，细节层 | 可从 context-clean-20261101 恢复 |
```

- 每行必须能追溯到 `context-clean` 里的 C/R/U 编号。**追溯不到 = 无声删除，禁止。**
- 舍弃只允许发生在非地板板块的展开细节上。
- 地板内的条目若进不了主文档，那不是舍弃，是**冲突** → 硬停报人工。

## 附录 B 存疑清单

放进不去的：拿不准板块归属的、禁替代表可能不完整的、来源自相矛盾的。每条写清「两种解释」与「需要人回答的那个问题」——**提问要能一句话回答**。

## 审查提示（给人工）

不必通读，看三处：

1. **五条红线是否都在、且没有被弱化表述。**
2. **术语表与禁替代表是否一致。**
3. **附录 A 里有没有你不认识的条目**——不认识 = 模型自作主张了。

## 失败行为

| 情形 | 行为 |
|---|---|
| 结论之间互相矛盾 | **硬停**：出冲突报告，不出新版本 |
| 超预算且地板无法再压缩 | **硬停**：出预算报告 + 三个结构方案，交人裁决 |
| 目标文件版本不低于本次 | **硬停**，不覆盖 |
| 拿不准某条该进哪个板块 | 进附录 B 并报告，不猜 |
| 输入缺「术语沿革」表 | 仍可产出，但附录 B 记一条「禁替代表不完整」 |

## 禁止

- 不写入输入不支持的任何论断；不替未决事项编结论。
- 不在主文档里使用 `![[...]]` 嵌入——被嵌入的内容可被编辑，冻结就失效；也违反自包含。
- 不无声删除「终态结论」里的任何条目。
- 不为凑满预算而扩写，不为显得完整而填充。
