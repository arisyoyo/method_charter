# method-core.md 模板

## 三条前提

1. **板块编号不许增删。** 下游对话按「§4.1 R3」这样的地址引用；改编号等于让所有既有引用失效。
2. **陈述层与指令层分开。** §1–§3 是陈述层（可逐字入稿、可核对）；§4–§6 是指令层（约束行为，不是内容）。混在一起会让「方法是什么」和「你该怎么写」焊死，版本 diff 时分不清变的是方法还是措辞要求。
3. **冻结。** 只有 merge 模式能改本文件；clean / distill 只读它。

## 板块填写指引

| 板块 | 层 | 写什么 | 不要写什么 |
|---|---|---|---|
| §1 | 陈述 | 主题、研究问题、为什么值得做 | 文献综述、摘要式复述、背景铺陈 |
| §2 | 陈述（地板） | 逻辑链、结构、贡献边界 | 实现步骤、参数、样例、代码 |
| §3 | 陈述（地板） | 定义 + 禁替代表 | 术语的讨论过程、曾用名的历史叙事 |
| §4 | 指令（地板） | 既定结论、行为禁令 | 建议、期望、语气要求 |
| §5 | 指令（预算内） | 允许改什么、改到什么程度 | 新的方法主张 |
| §6 | 指令（预算内） | 本次任务范围 | 长期约束（那些属于 §4） |

## 修改会话的范围声明（贴进新对话的第一条消息）

```text
【本次任务范围】
- 允许修改：第 3.2 节「实验分析」的第二、三段
- 不可触碰：§2 方法内核、§3 术语与禁替代表、§4 全部红线
- 行为规则：发现主文档错误或冲突时，不要就地修改，
  在回复末尾以【冲突上报】格式单独列出，由人工裁决
```

§6 与这段声明内容一致；§6 常驻文档，这段常驻对话。

## 冲突上报格式

```text
【冲突上报】
- 位置：§4.1 R3
- 类型：术语冲突 / 结论冲突 / 红线冲突 / 文档错误
- 问题：<一句话>
- 依据：<本文件哪句，与你发现的什么冲突>
- 建议：<改主文档 / 改正文 / 待定>
- 影响范围：<若不处理，会影响哪些段落或章节>
```

用固定标记，是为了让冲突可以被检索到、也可以被断言「本次没有冲突」。

## 首次使用校验话术

新对话第一次加载本文件时，先让它复述，再让它动笔：

```text
先不要开始写作。读完 method-core.md 后，用你自己的话复述三件事：
① §2.1 的逻辑链，五环各一句；
② §4.1 的事实红线，逐条点名；
③ 本次任务允许修改的范围。
复述完停下等我确认，再动笔。
```

复述走样的地方，就是这一版文档没写清或下游读岔的地方——这比事后审稿便宜得多。
