# clean 模式：折叠讨论到终态

把一段讨论压缩到**终态**。这不是摘要——**全部结论性信息都要留下，只删除过程性内容**。

## 边界

| | |
|---|---|
| 输入 | 当前对话上下文（可能很长） |
| 产物 | `./method/context-clean-<YYYYMMDD>.md`，模板见 `template-context-clean.md` |
| 不产出 | `method-core.md`——只有 distill / merge 模式能写 |
| 不追加 | `CHANGELOG.md`——变更史由 merge 维护 |

## 何时跑

由人显式调用后执行。进入时先确认属于哪种情形，写进产物的 `trigger`。

| 情形 | 说明 |
|---|---|
| 方法内核或术语发生了**已确认**变更 | 讨论收尾时调用 |
| 上下文接近上限，或即将被压缩 | **压缩前调用**——压缩之后再跑就晚了 |
| 会话收尾、交接、切换任务 | 调用 |
| 分叉前 | **不要调用**。以最近一次 `context-clean-*.md` + 当前 `method-core` 版本号作分叉点；忠实优先，凝练留到各分支收尾 |
| 其它主动触发 | 可调用，但 `trigger` 必须写清理由 |

**先判空。** 本次对话没有新生效结论时，不产出文件，只回一句「无可沉淀」。空跑会制造版本噪声。

## 执行方式：丢进子会话

在子会话里跑完，主对话只回收「产物路径 + 自检计数 + 未决条数」。把清理过程铺回主对话，等于把刚丢掉的过程又装回去。

## 步骤

1. **定位** `./method/`（不存在则建目录）。读 `method-core.md` 的 `version`，写进产物 frontmatter 的 `based-on`。
2. **识别修订链**（见下）。
3. **四类归类**：终态结论 / 被否定的分支 / 未决事项 / 过程性讨论。
4. **折叠**：每条链只输出终态；中间版本进否定分支索引，不保留正文。
5. **写产物**，按模板。frontmatter 记 `trigger`、`based-on`、四项计数。
6. **自检并回报**：逐链核对「是否已有终态」；回报路径 + 链数 / 结论数 / 否定分支数 / 未决数。**未决条数是人工审查的入口，写在第一行。**

## 判定顺序

对每一段发言按顺序问三个问题，第一个「是」即止：

1. **它改变了什么吗？** 没有 → 过程性，剔除。
2. **它被确认了吗？** 没被确认（提议、设想、疑问）→ 未决。
3. **它现在还算数吗？** 已被否掉或被后续版本取代 → 否定分支。否则 → 终态结论。

「明确采纳」的口径：**「可以 / 就按这个来 / 定为 X / 用 X」算确认；「我觉得可以 / 大概行 / 似乎更好」不算**，进未决。

## 四类判据

| 类 | 进入条件 | 产物形态 |
|---|---|---|
| 终态结论 | 被明确采纳 / 双方无异议 / 后续版本沿用 | 结论原文 + 限定条件 + 来源 |
| 否定分支 | 被明确否决、被后续版本取代、试过又撤回 | 一行方案描述 + 否定理由 + 归属链 |
| 未决 | 提出但未定、被搁置、双方各执一端 | 议题 + 双方立场 + 待定原因 |
| 过程性 | 解释、铺垫、重述、寒暄、工具操作、自我更正 | 剔除 |

## 修订链

### 识别

同一对象（同一章节、同一论断、同一定义、同一个数字口径）被改动两次以上，即构成一条链。

跨主题的讨论要**拆**成多条链分别折叠，不要强行合并成一条。

### 折叠

- **链的终点** = 最后一次确认的状态。只输出这个。
- **链的中间** = 每一次被取代的版本，各占否定分支索引一行。
- **方向反转**（先加后删）→ 终态是「删」；「加」进否定分支。
- **整条链被否决**（讨论一圈结论是「不做」）→ 否定分支索引，理由写「整体否决」。

### 自检不变式

> **每条修订链恰好产出一个结局**：一个终态结论、或一条未决、或一条整体否决。

因此 `chains = conclusions + pending + rejected_only`。对不上就是漏了或重了。

## 边界情形

| 情形 | 处理 |
|---|---|
| 同一结论不同阶段表述不同、语义相同 | 取**最后一次确认的原文**，逐字，不改写 |
| 数字、样本、口径被多次修正 | 终态数字 + 保留口径。**口径变化本身也是一条结论** |
| 术语被换过说法 | 终态术语 + 曾用变体，写入「术语沿革」。这是禁替代表的唯一来源 |
| 引用论文原文或他人文献 | 标「引用」，不算结论，不参与折叠 |
| 「先这样，之后再看」 | 未决，附当前临时状态 |
| 否定了某说法但没给替代 | 否定分支 + 未决（替代方案待定） |
| 问题被回答、答案后来被推翻 | 整链折叠到翻转后的终态；被推翻的答案进否定分支 |
| 关于「怎么写 / 用什么提示词」的元讨论 | 过程性——除非它产生了对写作的实际约束 |
| 情绪、寒暄、确认收到、工具操作日志 | 过程性 |
| 同一议题散落在对话两端 | 合并为一条链，终态取时间上最后的确认 |

## 失败行为

| 情形 | 行为 |
|---|---|
| 拿不准归哪一类 | 记入「未决」，注明「归类存疑」并列出两种候选。**禁止猜** |
| 同一议题存在互相矛盾的终态 | **硬停**：只出冲突报告，不出产物文件 |
| 上下文超长、无法一次处理 | 分窗折叠 → 归并 pass；归并不了就硬停，并列出未处理的区间 |
| 目标文件已存在 | 加 `-2` 后缀另存并报告，不覆盖 |

## 禁止

- 不压缩、不改写、不合并终态结论的表述；只删过程。
- 不把否定方案写成正面表述（「虽然…但…」是复活的前兆）。
- 不写「如上文所述」「参见前文」这类指代——产物必须能独立读。
- 不替人取舍：某条结论该不该进主文档，是 distill 与人的事。clean 只负责不漏。
